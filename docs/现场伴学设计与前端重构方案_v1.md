# 现场伴学设计与前端重构方案 v1

> 日期：2026-08-09（周日）｜状态：方案待实现（8/14 冻结前落地，8/10 前出 MVP）
> 依据：[需求对齐会议整理_v1_工作副本.md](./old/需求对齐会议整理_v1_工作副本.md)（含 8/9 夜补充）+ 原始会议转写 `会议内容.txt`
> 说明：标注（已定）的条目为产品侧已确认或已授权代定；标注（待确认）的为下次会问企业或后续再定。

## 1. 背景与一句话方案

企业把 AI 伴学定位为"课后助教"：随堂当堂完成、学生口述 AI 语音转文字、AI 只做追问和启发、评分看底层逻辑不看辞藻、教师端必须轻量。

本版落地方案：**不做真正的学生端 App**，用"同一前端双路由"低成本模拟多端；**AI 追问做实并长在教师端**（AI 出追问建议卡，教师执行追问）；**家长端只留接口**；**现场反馈只在教师端**；前端按"直播间可用"重构为**「课堂模式 + 工作台模式」**。

**范围边界（2026-08-09 确认）**：直播音视频、学生开麦、学生端 UI、实时音频流属于维学直播平台的现成基础设施，**不是我们的交付范围**。我们做 AI 伴学层（追问/复述检测/评估/评语/报告）+ 教师端 + 接入适配器（接收学生音频、转写结果或平台状态回调）。学生窗口在本版仅作为**演示占位 + 接入适配器**，用于讲通产品故事；真实输入来源待第二次会向企业确认。

## 2. 已拍板决策（已定）

| 决策点 | 结论 | 说明 |
|---|---|---|
| 多端演示 | 同仓库双路由：`/student/:id` 学生窗口（演示占位）+ 教师端一键开窗 | 真实部署取决于企业确认的输入边界；若学生端由我们实现，只换前端壳、后端不动 |
| AI 追问 | 本版做，入口在教师端（课堂模式） | 学生端界面不做 |
| 多轮上限 | ≤ 3 轮（含首轮） | 防现场演示拖沓 |
| 家长端 | 只做数据模型 + 报告生成 API | 前端页面不做 |
| 现场反馈 | 只在教师端屏幕呈现 | 教师决定如何转述 |
| 评级按钮 | 👍 表达完整 ／ ➕ 需引导 ／ ⚠️ 复述或未表达 | 教师独立判断，AI 只预填不决定 |
| 现场入口 | 新增顶级「课堂」模式，作为默认页 | 原 6 个 tab 归入「工作台」模式 |
| 学生端开麦 | 演示占位：学生窗口做"看起来能开麦"的模拟交互 | 真实场景开麦/状态来自维学直播平台，我们只做接入适配器 |
| 范围边界 | 不造直播音视频、学生端 UI、实时音频流 | 直播平台基础设施归企业；我们做 AI 层 + 教师端 + 接入适配器 |

## 3. 多端低成本演示方案（已定）

**录入通道抽象是前提**：无论哪个端录入，都走同一导入 API，请求带 `source`（`student_device` / `teacher` / `manual_text`）。后端不关心前端是谁，将来真做多端只换壳。

### 3.1 学生窗口（演示占位 + 接入适配器）

- 新增路由 `/student/:studentId`，页面只做四件事：看故事情景与题目、**开麦口述**、提交、查看"已提交/处理中/已处理"状态。
- **定位**：本窗口是**演示占位**，用来讲通"学生口述 → 状态流转 → AI 评估"的产品故事，并充当**接入适配器**——真实产品中，学生的口述音频/转写结果可能来自维学直播平台导出、飞书妙记或学生端上传，我们只消费结果，不采集。
- **开麦交互**：演示时用 `MediaRecorder` 尝试真实采集；权限被拒或环境不允许时降级为"模拟录音"（倒计时 3 秒 + 录音动效）并用 mock 转写，界面明示为模拟。真实产品里这个动作由直播平台完成，我们不对接实时音频流。
- 演示时教师在课堂模式点「打开学生窗口」，弹出多个浏览器窗口模拟多个学生设备（若企业确认学生端由我们实现，再升级为真实页面，后端无需改动）。

### 3.2 兜底

- ASR 不可用/麦克风被拒：学生窗口和教师端都支持粘贴文本，演示不卡壳。
- 纯前端 demo 模式（GitHub Pages）下学生窗口走 demoClient，断网可演示。

### 3.3 学生状态机与实时同步（新增）

**发言管道状态机**（演示时由学生窗口模拟驱动，教师端实时可见；真实产品中这些状态来自平台回调/转写进度，我们只呈现）：

```
未发言 → 正在发言 → 已发言 → 处理中 → 已处理
```

审阅层叠加在"已处理"之后：待教师确认 → 已确认（可带 复述风险 / 需引导 标记）。

| 状态 | 含义 | 触发方 |
|---|---|---|
| 未发言 | 本轮还没开麦 | 初始 |
| 正在发言 | 学生端麦克风录音中（教师端卡片红点脉动） | 演示：学生窗口开麦；真实：平台状态回调 |
| 已发言 | 录音已提交，等待处理 | 演示：学生窗口点提交；真实：平台/学生端上传完成回调 |
| 处理中 | ASR 转写 / 评估进行中 | 后端 |
| 已处理 | 转写 + AI 草稿就绪，进入教师审阅 | 后端 |

**实时通道（抽象为 statusBus，两端可切换）**：

- 纯前端 demo 模式：同浏览器内用 **BroadcastChannel** 同步（学生窗口 ↔ 教师课堂模式），无需后端，状态天然"看起来实时"。
- 真实模式：FastAPI WebSocket / SSE 推送；时间紧先 2s 轮询兜底。
- 教师端只收状态事件，**不收听音频**；音频本身仍走"学生录音文件 → 后端 ASR"的异步链路。

## 4. AI 追问教师端伴学工作流（7 步，已定）

这是课堂模式的核心流程，也是演示主线：

1. **选学生**：教师点学生卡片。
2. **录入首轮**：学生口述（学生窗口提交或教师端录音/粘贴）→ ASR 转写 → 生成第一轮 `raw_text`。
3. **AI 追问建议卡**：伴学引擎基于首轮回答生成 1~2 条脚手架追问（只追问、不告知、禁填空式），并做**复述检测**，返回 `scaffold_status`：合格 / 需继续 / 复述风险。
4. **教师执行追问**：追问卡默认折叠，教师点开、决定照读或自己追问——**追问只能由教师发出**，AI 不直接和学生对话。
5. **学生补充**：教师录入第二轮，追加到同一 response 的对话轮次；可循环至 3 轮。
6. **评估**：对话结束后，评估引擎基于完整对话历史（含 AI 追问记录、复述标记）一次调用输出五维度草稿 + 评语草稿（合并调用，现场不等待）。
7. **轻量审阅**：教师一键采纳 AI + 整体评级按钮 + 轻批注；确认后才生效（现有教师决策门保留）。评语只出在教师屏；家长端只调预留接口。

## 5. 教师省力 vs 不代劳边界（已定）

原则：**AI 只给"建议和草稿"，教师做"选择、执行和确认"**。

| AI 代劳（省力） | 教师必须掌握（不代劳） |
|---|---|
| 录音转写、文本清洗 | **追问的执行**——AI 只给话术建议，老师来问 |
| 追问话术建议卡 | **对每个孩子的最终判断**——评级按钮是教师独立决定 |
| 维度评分草稿 + 理由 | **是否采纳 AI 评分**——一键采纳但确认权在教师 |
| 评语草稿（正反馈基调） | **评语定稿与发送** |
| 复述风险提示 | **是否换一种方式再追问**——AI 只提示，不问 |

防代劳的机制：追问卡默认折叠且必须教师手动采用；复述风险只标黄提示；评估草稿必须教师确认才落库；评级由教师点。这些机制同时是答辩亮点："AI 在每个主观判断节点都停在建议层"。

## 6. 家长端接口预留（已定）

- 新增只读接口 `GET /api/students/{sid}/report`：返回结构化家长报告（五维度摘要 + 教师点评 + 进步点 + 下一步建议）。
- 不新建前端页面；数据可复用现有评分/评语/聚合逻辑计算，无需新表。
- 未来家长端/飞书机器人直接消费该接口。

## 7. 数据模型与 API 改动（接口解耦，为多端预留）

- 新增 `companion_turns` 表：`response_id`、`role`（student / ai_suggestion / teacher）、`content`、`turn_type`（追问 / 启发 / 反例 / 复述标记）、时间戳。一题一生一会话，多轮即追加轮次。用表不用 JSON，避免并发写冲突，未来学生端直连也稳。
- `StudentResponse` 关联该表；`source` 字段扩展取值（`student_device` / `teacher` / `manual_text`，含义见下）；新增 `processing_status` 字段（not_started / recording / submitted / processing / processed），教师端与接入适配器共享。
- **输入来源待企业确认（不阻塞开发）**：真实场景下学生口述的音频/转写由谁提供（平台导出 / 飞书妙记 / 学生端上传）？本版按"统一导入接口 + source 标记"抽象，三种来源都落同一个入口。
- 新增伴学 API：
  - `POST /api/companion/{response_id}/suggest-turn`：返回追问建议 + 复述检测结果。
  - `POST /api/responses/{rid}/turns`：追加学生回答轮次（同时更新 raw/cleaned text）。
  - `GET /api/companion/{response_id}`：对话历史（教师端/学生端同读）。
  - `PATCH /api/responses/{rid}/status`：接入适配器上报录音中/已提交，教师端读取；导入接口扩展 `source=student_device`（演示用）。
- 状态实时推送：demo 模式走 BroadcastChannel（演示占位），真实模式走 WebSocket/SSE 或平台回调（P1，先轮询兜底）。
- 评估引擎输入扩展：`evaluate` 接收对话历史；prompt 注入对话记录 + 引导边界 + 五维度映射 + 负面清单。
- 快速评估：清洗 + 五维度评分 + 评语草稿合并为一次 LLM 调用。

## 8. 前端重构：课堂模式 vs 工作台模式（核心改动）

### 8.1 现状问题

现有 6 个 tab（管理 / 智能评估 / 评语生成 / 备课辅助 / 学情报告 / 标签库）是"教师坐办公桌改作业"的工作流：

- tab 心智是后台系统，上课时切 tab 本身就是摩擦；
- 智能评估是逐份详情 + 上一位/下一位翻页，适合批量审阅，不适合课堂逐个跟进；
- 信息密度高（维度卡、推理链要读），老师上课没空读；
- 录音入口埋在「管理 → 录音录入」，上课时要主屏直达；
- 批量思维（AI 评估全班）vs 课堂思维（一个学生一个学生走完）；
- 大量输入靠打字（批注、评语），课堂里是负担。

### 8.2 双模式架构（已定）

App 顶级拆成两个模式，头部切换：

- **「课堂」模式（Live Cockpit，默认页）**：直播间上课专用，围绕"环节节奏 + 7 个学生"设计。
- **「工作台」模式（Workbench）**：保留现有 6 tab，供课前备课、课后批量审阅与报告用。

两者共用同一套 API、store 和数据模型；课堂模式的确认结果直接进入工作台的审阅队列。

### 8.3 课堂模式界面设计

- **顶栏**：班级名、当前环节（可选，P1）、发言进度（x/7 已发言）+ 确认进度（y/7 已确认）、「打开学生窗口」按钮。
- **主体**：7 张学生卡片的 grid，一屏放下不滚动：
  - 姓名 + 年级/梯段标记（低/中/高）；
  - 状态色块（发言管道 + 审阅层）：灰=未发言、红点脉动=正在发言、蓝=已发言、黄=处理中、绿=已处理、橙=复述风险、深绿勾=已确认；
  - 大号录音按钮（触屏友好）+ 学生窗口提交的到达提示；
  - AI 草稿出来后：👍/➕/⚠️ 三个评级大按钮 + 「采纳 AI」，一次点击完成；
  - 卡片可展开：对话轮次时间线、AI 追问建议卡、维度草稿、轻批注框。
- **追问建议卡**：默认折叠；展开后显示建议话术 + 「采用」按钮（采用后进入教师话术气泡，可直接照读）。
- **兜底**：粘贴文本入口常驻，ASR 慢/失败不阻塞课堂。
- **可选增强（P1）**：空格键录音、快捷键评级、语音输入批注。

### 8.4 工作台调整

- 现有 6 tab 原样保留，语义改为"课后/课前办公"。
- 「智能评估」保留批量审阅，并可一键回到课堂模式继续未完成学生。
- 「备课辅助」扩展为**课前反馈包**（上次作业状态、优秀作业展示、破题回顾重点）——对接企业"下节课前轻量反馈"。
- 「评语生成」保持，模板按正反馈/闪光点基调改写。

### 8.5 技术实现要点

- `App.jsx` 加顶级模式开关；课堂模式新增 `LiveCockpit.jsx`、`StudentCard.jsx`、`StudentWindow.jsx`（路由 `/student/:id`）等组件。
- 现有页面组件不删，仅归入工作台；store/API 复用。
- 课堂模式所有写操作都走既有 review/import 接口 + 新增 turns 接口，保证工作台数据同步。

## 9. 评分口径融合（与现有打分系统融合）

- **（2026-08-11 已落地）五维度为唯一核心评判标准**：评估引擎直接输出五维度
  `position`（立意）/ `material`（选材）/ `structure`（结构）/ `language`（语言）/ `perspective`（视角），
  三个认知梯段共用同一套维度定义与等权权重（同一套标准），年级差异通过合格线与评估重点表达。
- 负面清单写进三个梯段 prompt：不评流利度、不评好词好句、不评引经据典、只看底层逻辑。
- 低年级合格线 = "敢说、说清楚"（观点表达完整），融入"立意"维度的描述与提示词。
- 输出增加 `bonus_flags`（有自己 / 有新意）：命中可升级评级（A → A+），不量化分数。
- 评语模板按正反馈、发现闪光点基调改写。
- 三年级梯段边界配置化（1-3 归属待企业确认后一行切换）。

## 12. 遗留待确认（不阻塞开发）

- **输入边界（2026-08-11 已答）**：AI 伴学发到**企业自研 App + 微信公众号**；转写由**平台后台 AI 识别、实时导出**，我们对接平台导出（飞书妙记路线不再需要）。
